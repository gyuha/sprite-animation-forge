## 계약과 다르게 한 것 (사유)
- 기준선 테스트의 하드코딩 문자열 `video_prompt@1` → `@2` 2곳(`webui/server/tests/test_jobs_video.py`, `webui/web/e2e/video.spec.ts`) — #28~29에서 내가 만든 테스트이며 버전 상승의 직접적 결과. 테스트 ID는 그대로.
- 계획의 "attack 20% ±2%p, walk 0"는 우리 정사각 캔버스에 맞춰 해석: 기본 가운데 배치가 이미 위 여백 20%라 attack을 20%로 두면 기본과 구별되지 않아 attack·jump를 30%/캐릭터 55%로, walk·run은 6%/80%로 정했다(여백 0%는 머리가 잘릴 위험이라 안전 여백 6%). sprite-gen의 "정지 그림 위 20% 행 확장"과 같은 수치가 아니다(문서에 명시).

## 학습 / 주의
- 정사각 캔버스에서 위 여백만 바꾸면 아래 여백이 줄어 발 쪽이 빠듯할 수 있다(walk 80% → 발 아래 14%). 실제 영상 모델이 가장자리를 어떻게 다루는지는 미검증 [낮음].
