# 2026-10-01 — M5-c 스튜디오: 서버 process의 set이 누적되지 않아 UI가 전체 파라미터를 보내야 함

## Plan vs actual
- What went as planned: 플레이어·오버레이·QC·권장 조치·재처리·attempt 기록, Vitest 36건 추가.
- Divergences: `POST …/process`의 `set`은 직전 재처리 위가 아니라 plan 값 위에 적용된다(CLI `process --set`과 같은 의미). 슬라이더 하나만 보내면 이전에 조정한 값이 조용히 초기화된다. 문서(docs/10)에 이 의미가 적혀 있지 않았고 에이전트가 요청 본문 테스트로 UI 쪽에서 우회(항상 12개 키 전부 전송). 같은 시점에 `Direction` 타입이 서버(down|up|right|left)와 달랐던 foundation 결함도 발견·수정.

## Learnings
- Do differently next time: API 의미(누적/비누적, 덮어쓰기)는 타입으로 드러나지 않으므로 docs/10에 한 줄 명시하거나 서버가 `process.json.params`를 기준으로 병합하게 하는 쪽이 UI 우회보다 안전하다(후보). 프런트가 먼저 만들어진 백엔드 타입을 손으로 재정의한 곳(Direction)은 OpenAPI에 enum으로 노출시켜 생성 타입을 쓰게 한다. 응답이 dict로 타입 없는 라우트(health, characters)가 수기 타입을 낳는 점도 Pydantic 모델화 후보.
